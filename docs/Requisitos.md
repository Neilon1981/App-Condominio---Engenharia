# 📄 Documentação de Requisitos

## ✅ Requisitos Funcionais (RF)

- **RF01:** O sistema deve permitir o **cadastro, leitura, atualização e exclusão (CRUD)** de moradores e síndicos.  
- **RF02:** O sistema deve ter **login** com níveis de acesso diferenciados (Morador x Síndico).  
- **RF03:** O sistema deve permitir **agendamento e cancelamento de reservas** de áreas comuns.  
- **RF04:** O sistema deve permitir a **abertura e atualização de status de ocorrências**.  
- **RF05:** O sistema deve enviar **notificações push** de comunicados e boletos.  

---

## ⚙️ Requisitos Não Funcionais (RNF)

- **RNF01:** O aplicativo deve ser **responsivo e multiplataforma** (Android e iOS).  
- **RNF02:** Os dados devem ser **criptografados**, garantindo a privacidade conforme a **LGPD**.  
- **RNF03:** A interface deve seguir princípios de **acessibilidade**, especialmente para usuários idosos.  

---

## 📋 Observações
- Estes requisitos foram definidos com base nas entrevistas realizadas com **síndicos e moradores**.  
- Servirão como base para a modelagem dos **casos de uso (UML)** e dos **processos (BPMN)**.  
- Devem ser revisados e validados ao longo do desenvolvimento do protótipo (MVP).
